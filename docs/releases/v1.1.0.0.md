# Jeninnet.Assertions v1.1.0.0 — The Assertion Surface Expands

v1.1.0.0 is the release where the assertion surface becomes more complete without becoming less predictable. It adds typed string parsing, positive and reverse architecture rules, a deeper snapshot workflow, and automated migrations for two more assertion libraries. The existing values, collections, time, async, HTTP, JSON, XML, snapshots, reflection, and IO assertions remain available under the same MIT license and the same zero-test-framework-dependency rule.

## Highlights

### Typed string parsing

`BeParsableInto<T>` and `NotBeParsableInto<T>` turn parsing checks into assertions instead of `TryParse` ceremonies. They work with any `IParsable<T>` on `net8.0` and newer, expose the parsed value through `Which`, and accept an explicit `IFormatProvider`. The provider-less overload uses the invariant culture, so a test does not change meaning when a developer moves to another machine.

```csharp
var port = "8080".Should().BeParsableInto<int>().Which;
var price = "1.234,56".Should().BeParsableInto<decimal>(CultureInfo.GetCultureInfo("de-DE")).Which;

"not-a-port".Should().NotBeParsableInto<int>();
```

Parse failures become assertion failures with the target type and a short reason; parser exceptions do not leak through the test.

### Architecture direction, not only forbidden dependencies

The architecture surface previously answered the negative question: “must not depend on.” v1.1 adds the positive and reverse questions:

- `DependOn` / `DependOnAny` require an edge to exist.
- `OnlyBeDependedOnBy` and `NotBeDependedOnBy` inspect incoming edges.
- `ArchitectureLayer` plus `FollowLayers` declares a layer map once, assigns each type to the most specific namespace prefix, allows same-layer edges, and reports cross-layer violations with the concrete path.

```csharp
var layers = new[] {
    new ArchitectureLayer("Domain", "Store.Orders.Domain"),
    new ArchitectureLayer("Application", "Store.Orders.Application").DependsOn("Domain"),
    new ArchitectureLayer("Infrastructure", "Store.Orders.Infrastructure").DependsOn("Domain"),
};

AllTypes.From(typeof(Order).Assembly).Should().FollowLayers(layers);
```

The rule is reflection-level. Method bodies and IL remain out of scope, and incoming scans cover the assemblies of the selected types. Those limits are documented because a test that pretends to see more than it can is worse than a smaller, honest test.

### Snapshot workflow depth

Snapshots now cover the daily sources of noise without adding a dependency:

- `ScrubMachineName`, `ScrubUserName`, and `ScrubGuid` are convenience scrubbers applied after explicit scrubbers.
- `IgnoreJsonProperty("$.metadata.timestamp")` removes one JSON property path before comparison.
- `IgnoreMembersNamed("etag", "timestamp")` removes volatile members at every depth.
- `UseProjectRelativeDirectory()` resolves the default snapshot folder from the nearest `*.csproj`, with a caller-relative fallback and per-directory caching.

Missing paths are no-ops, invalid JSON is left unchanged, and explicit scrubbers keep their order. The snapshot still follows the deliberate review model: `.received` is a candidate, `.verified` is the contract, and `JENINNET_SNAPSHOT_UPDATE=1` is the explicit bulk-accept switch.

### Automated migration for Shouldly and NFluent

The analyzer now recognizes simple Shouldly and NFluent shapes behind separate rule IDs:

- `JNA2001` for Shouldly equality, null/boolean, containment, emptiness, and statement-position throw.
- `JNA2002` for NFluent `Check.That(...)` equality, null/boolean, containment, emptiness, size, and statement-position throw.

Both use the existing speculative-binding contract: a suggestion appears only when the generated `Should()` call is proven to compile. Tolerance, comparer, culture, custom-message, chained-result, approval-snapshot, and `dynamic` shapes remain manual. Fix All is supported.

### Measured peer comparison

The benchmark project now measures the same hot verbs and scope scenarios against AwesomeAssertions 9.6.0, Shouldly 4.3.0, and NFluent 3.1.0 on the same machine and runtime. The published tables include mean time and allocations for success and failure, plus explicit notes where scope semantics differ. The results are evidence, not a universal ranking; the README and chapter 9 carry the environment and the caveats.

## Compatibility

- Core package target frameworks: `netstandard2.0`, `net6.0`, `net8.0`, `net10.0`.
- `BeParsableInto<T>` / `NotBeParsableInto<T>` require `net8.0` or newer because `IParsable<T>` is not available on the older targets.
- HTTP assertions require `net6.0` or newer.
- The core has no test-framework dependency and no third-party runtime dependency beyond BCL shims on old target frameworks.
- No intentional breaking public API changes. All changes are additions; the API baseline is regenerated and committed.
- Package version is `1.1.0` on NuGet; the repository tag is `v1.1.0.0`.

## What this release is about

The assertion library does not become better by accumulating verbs. It becomes better when each new verb closes a real gap, states its limits, and keeps the failure message readable. v1.1 adds four such closures: typed parsing, layer direction, snapshot noise control, and migration reach. The next release should follow the same rule: add only what the evidence supports.
